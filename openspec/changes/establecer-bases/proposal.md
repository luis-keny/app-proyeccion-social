# Establecer las bases del sistema

## Why

La aplicación es una demo. Necesitamos requisitos claros, decisiones revisables y documentación útil antes de integrar identidad, persistencia y asistencia real.

## What Changes

- Organizar docs en producto, arquitectura, datos, desarrollo, operación y decisiones.
- Mantener README como entrada humana, AGENTS como flujo operativo y CLAUDE como referencia.
- Usar documentación vigente y concisa, sin versiones ni diarios; centralizar preguntas y evidencia en OpenSpec.
- Preservar reglas confirmadas: una sede, sin inscripción, crédito fijo, confirmación de identidad y recurrencias finitas.
- Proponer arquitectura modular, modelo de datos y escenarios sin presentarlos como implementados.

## Capabilities

### New Capabilities

- `activity-scheduling`: publicación, sesiones finitas y cancelación individual.
- `attendance-recording`: identificación, confirmación, autorización y crédito único.
- `student-progress`: consulta propia de horas y desglose por ciclo.

### Modified Capabilities

Ninguna: todavía no hay baseline consolidada.

## Impact

Archivos documentales, README, AGENTS, CLAUDE y configuración OpenSpec. No cambia código de aplicación, dependencias, infraestructura ni datos reales.

La reorganización documental está autorizada. Las capacidades objetivo y decisiones técnicas pendientes no se implementan ni consolidan automáticamente.
