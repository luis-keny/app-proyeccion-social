# SDD y documentación

**Estado:** aceptada por instrucción humana.

Necesitamos trabajo comprensible y controlado. Usamos OpenSpec para requisitos, propuestas, tareas y evidencia; README como entrada humana; AGENTS como instrucciones operativas y CLAUDE como referencia.

El humano define necesidades, acepta propuestas, autoriza impactos y acepta resultados. Cada actualización mantiene el documento correspondiente. La alternativa de ejecutar propuestas sin revisión no cumple este control.

La documentación usa nombres descriptivos, contenido vigente y una ubicación por tema. El historial queda en Git/OpenSpec. Ver [reglas de trabajo](../../AGENTS.md).

Para Git se adopta Ship/Show/Ask y trabajo habitual en la rama actual. Las ramas o worktrees se reservan para modificaciones grandes que requieran aislamiento, frente a crear una rama por cada tarea. La modalidad determina cuándo revisar, sin ampliar autorizaciones. Ver [estrategia de Git](../development.md#estrategia-de-git-ship--show--ask).
